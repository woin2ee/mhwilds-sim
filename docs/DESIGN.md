# 설계 문서

몬스터 헌터 와일즈 비공식 방어구 세팅 시뮬레이터. 정적 사이트(GitHub Pages)로 배포되며 모든 계산은 브라우저에서 한다.

## 1. 목표 (1순위 기능)

1. **수동 세팅** — 무기·방어구 5부위·호석·장식주를 직접 골라 최종 스킬/방어력/내성/남은 슬롯을 확인한다.
2. **스킬 검색** — 원하는 스킬(레벨)을 고르면 가능한 방어구 조합을 찾는다.
3. **비선호 스킬 제외** — 원하지 않는 스킬을 고르면
   - `exclude`: 그 스킬이 붙은 방어구·호석·장식주를 아예 후보에서 뺀다.
   - `mark`(기본, '표시만'): 결과에 포함해 다른 결과와 같은 정렬로 섞고, 화면은 결과 안의 비선호 스킬에만 표시한다.
4. **결과 정리** — 요구 스킬 관점에서 동등한 방어구는 한 결과로 묶고(부위별 대체 후보로 표시) 결과 수를 줄인다.

## 3. 데이터

`scripts/build-data.mjs` 가 [MHDB](https://docs.wilds.mhdb.io) API(ko/en/ja)에서 받아 `src/data/types.ts` 의 `GameData` 형식으로 저장한다.
갱신은 `npm run data:update` 후 결과 파일을 커밋한다. 데이터 출처: [mhdb-wilds-data](https://github.com/LartTyler/mhdb-wilds-data) (GPL-3.0).

- 이름은 `Names {ko,en,ja}`. 화면 표시는 `nameOf(names)` (현재 ko).
- 방어구의 `skills` 에는 armor 스킬만 있다. 시리즈/그룹 스킬은 `setId → ArmorSet.setSkillId/groupSkillId` 로 센다.
- 거극 아티어 무기는 데이터에 표시가 없고 붙는 시리즈/그룹 스킬도 무기마다 무작위라, 무기는 `gogmaArtian.ts` 에 게임 id 로 적고
  붙은 스킬은 세팅에 담는다 (§4).
- 제작 호석(`talismans`)은 등급별로 펼쳐져 있고 `isMaxRank` 로 최고 등급을 표시한다. 슬롯은 없다.

## 4. 게임 규칙 (와일즈)

| 항목 | 규칙 |
|---|---|
| 슬롯 종류 | 무기 슬롯(무기·호석) / 방어구 슬롯(방어구·호석). 레벨 1~3 |
| 장식주 | 같은 종류 슬롯에만, `장식주 크기 ≤ 슬롯 레벨` 이면 장착. 무기 장식주는 무기 스킬만, 방어구 장식주는 방어구 스킬만 준다 (데이터로 확인) |
| 스킬 레벨 | 출처를 모두 합산하고 `maxLevel` 에서 자른다 |
| 시리즈 스킬 | 같은 `setSkillId` 를 가진 방어구 수(α/β/γ 합산) + 거극 아티어 무기. 2부위 → 1단계, 4부위 → 2단계 |
| 그룹 스킬 | 같은 `groupSkillId` 를 가진 방어구 수(세트가 달라도 합산) + 거극 아티어 무기. 3부위 → 발동 |
| 제작 호석 | 방어구 스킬만, 슬롯 없음 |
| 감정 호석 | 사용자가 직접 입력 (`CustomTalisman`). 무기 스킬 가능, 무기/방어구 슬롯 가능 |
| 방어구 초월 | `transcend.ts` 참고. 레어도 5: 3칸 모두 +1, 레어도 6: 앞 2칸 +1 (빈 칸 → Lv1, 최대 Lv3), 7·8: 슬롯 변화 없음. 최대 방어력 +16/+12/+10/+8 |
| HR 100 장비 | ★9·★10 퀘스트(HR 100 이상)나 HR 100 미션에서만 나오는 소재·해금이 필요한 장비. 데이터에 없어서 `hunterRank.ts` 에 게임 id 로 적는다: 방어구 8세트(이그졸스γ·다하딜라γ·슈바르카γ·고그α/β·오메가 의상α·푸푸로페이크α·퀸α), 제작 호석 8개(모두 Ⅲ, 같은 계열의 아래 등급은 HR 100 전에 만든다). 레다젤트γ·투나물γ 는 ★8 HR 50 이라 넣지 않는다 |
| 무기 | 검색에서는 고정. 무기 스킬 + 무기 슬롯 제공 |
| 거극 아티어 무기 | 시리즈 스킬·그룹 스킬이 하나씩 무작위로 붙고 각각 방어구 1부위로 센다 (무기 혼자서는 발동하지 않음). 무기 종류마다 격화 타입(공격·회심·속성)별 3개. 데이터에 표시가 없어 `gogmaArtian.ts` 에 게임 id 로 적고, 붙은 스킬은 사용자가 골라 `WeaponChoice` 의 `setSkillId`/`groupSkillId` 에 담는다 (직접 입력 무기에도 넣을 수 있고, 거극 아티어가 아닌 DB 무기의 값은 무시). 붙을 수 있는 스킬은 따로 거르지 않고 모든 시리즈/그룹 스킬에서 고른다 |

결과적으로 **방어구 스킬**은 방어구·호석·방어구 장식주(방어구 슬롯 + 호석의 방어구 슬롯)로만,
**무기 스킬**은 무기·호석·무기 장식주(무기 슬롯 + 호석의 무기 슬롯)로만 얻는다. 두 풀은 독립적이다.

## 5. 계산 코어 (`computeBuild`)

`computeBuild(db, build, customTalismans)` → `BuildSummary`:
스킬 합계(출처 포함, 최대 레벨 적용), 시리즈/그룹 스킬 단계, 방어력(base/max), 내성, 슬롯별 장식주(유효성), 빈 슬롯.
보조 함수: `activeSkillLevels`, `missingRequirements`, `unwantedSkillsOf`(무기 자체 스킬은 비선호로 세지 않음).
`BuildState.decorations[key][i]` 의 i 는 `ResolvedEquipment.slots` 의 순서(방어구·무기는 레벨 내림차순, 호석은 사용자 입력 순서).

## 6. 검색 엔진 (`src/core/search/engine.ts`)

`runSearch(db, request, hooks) → SearchResponse` — 순수 동기 함수. 워커가 감싸서 실행한다.

### 6.1 입력 정리
- `required` 를 합치고(같은 스킬은 큰 레벨) `maxLevel` 로 자른다. armor/weapon 스킬(`R_pts`)과 set/group 스킬(`R_bonus`, 요구 레벨 → 필요한 부위 수)로 나눈다.
- 무기는 고정: 무기 스킬을 기본 점수로, 무기 슬롯을 무기 슬롯 풀로 쓴다.
  거극 아티어 무기에 붙은 시리즈/그룹 스킬은 그 `R_bonus` 의 필요한 부위 수에서 1을 뺀다 (방어구로 채울 부위 수).
- 후보 필터
  - 방어구: `includeLowRank`(rank === 'low' 제외 여부), `excludedArmorIds`, `exclude` 모드면 비선호 스킬 보유 방어구 제거.
  - 호석: `request.talismans`. `exclude` 모드면 비선호 스킬 보유 호석 제거. 비어 있으면 '호석 없음' 하나.
  - 장식주: `R_pts` 스킬을 하나라도 주는 장식주만. 비선호 스킬이 붙은 장식주는 먼저 제외하고 시도하며,
    `mark` 모드에서 그걸로 안 될 때만 포함해 재시도한다(그 결과에는 비선호 스킬이 들어간다).
  - 장식주 없이 찾기(`useDecorations: false`): 후보 장식주가 없다. `R_pts` 가 모두 '장식주로 못 채우는 스킬'(`none` 풀)이
    되어 방어구·호석·무기 점수만으로 판정하고(가지치기 2가 정확한 판정이 됨), 슬롯은 모두 남는 슬롯이 된다.
  - 어떤 부위의 후보가 0개면 그 부위는 '미장착'(빈 클래스) 하나로 둔다.

### 6.2 동등 클래스로 압축
부위별로 방어구를 다음 키로 묶는다. 키가 같으면 요구 조건 충족 여부와 장식주 배치가 완전히 같다.
- `R_pts` 각 스킬의 점수 (요구 레벨에서 자름)
- 초월 반영 슬롯 (레벨 내림차순)
- `R_bonus` 각 스킬에 대한 소속 여부 (setSkillId/groupSkillId 일치)
- 보유한 비선호 스킬 목록 (mark 모드)

클래스 멤버는 방어력(초월 반영 max) 내림차순, `[0]` 이 대표. 호석도 같은 방식(점수·슬롯(종류+레벨)·비선호)으로 묶는다.

### 6.3 탐색
- 무기 스킬 풀은 방어구와 무관하므로 **호석 클래스마다 한 번** 무기 장식주 충족 가능 여부를 계산해 불가능한 호석 클래스를 버린다.
- 방어구 5부위(클래스 수가 적은 부위부터) × 호석 클래스를 DFS. 상태: 스킬 점수, 시리즈/그룹 부위 수, 방어구/무기 슬롯 개수(레벨별).
- 가지치기 (모두 낙관적 상한이어야 함 = 정답을 버리면 안 됨)
  1. 시리즈/그룹: 현재 부위 수 + 남은 부위 중 해당 소속 클래스가 있는 부위 수 < 필요 부위 수 → 컷
  2. 스킬별: 현재 점수 + 남은 부위 최대 점수 + (장식주가 있는 스킬이면 남은/현재 슬롯으로 얻을 수 있는 최대치) < 요구 → 컷
  3. 풀별 총량: Σ(부족분) > 현재 슬롯 잠재력 + Σ(남은 부위별 최대 잠재력) → 컷
     (슬롯 잠재력 = 그 슬롯에 들어갈 수 있는 장식주가 주는 요구 스킬 점수 합의 최댓값).
     장식주 최소 크기(1/2/3)별로 스킬을 나눠 각각 검사한다 (Lv3 장식주로만 얻는 스킬은 Lv3 슬롯만 센다).
- 유망한 클래스부터 탐색해, 상한에 걸려 중단돼도 좋은 조합이 먼저 잡히게 한다: 잠재력(Lv1 임계의 점수 + 슬롯 잠재력)
  내림차순, 같으면 결과 정렬 기준 순(`slots`: 슬롯 점수 → 방어력, `defense`: 방어력 → 슬롯 점수).
  장식주 없이 찾으면 잠재력이 모두 0이고 리프가 모두 결과라서 정렬 기준 순서만 남는다.
- 리프: 장식주 채우기(6.4)가 가능하면 결과로 기록.

### 6.4 장식주 채우기 (정확한 판정)
풀(방어구/무기)별로 독립 계산. 상태 = (스킬별 부족분, 레벨별 남은 슬롯 수), 전역 메모이제이션.
부족분이 남은 첫 스킬을 고르고, 그 스킬을 주는 장식주를 하나씩 시도한다: 그 장식주가 들어가는 **가장 작은** 슬롯에 넣고(교환 논법상 최적) 부족분을 줄여 재귀.
여러 해 중 남는 슬롯 점수(아래)가 가장 큰 배치를 고른다. 마지막에 개수 기반 배치를 실제 장비·슬롯 인덱스로 옮긴다
(큰 장식주부터 맞는 가장 작은 실제 슬롯에).

### 6.5 결과
- 결과 1건 = 부위별 클래스 + 호석 클래스 조합. `armor[kind]` = 클래스 멤버 id 들, `talismans` = 호석 클래스 멤버들.
- `skillLevels`, `freeSlots`, `defense`, `unwantedSkills` 는 대표 조합 기준 (`computeBuild` 와 일치해야 함).
- 정렬: `slots` = 남는 슬롯 점수(Σ level², 무기·방어구 슬롯 모두) 내림차순 → 방어력 내림차순, `defense` = 방어력 → 남는 슬롯.
  비선호 스킬이 든 결과도 따로 모으지 않고 같은 기준으로 섞으며, 두 기준이 모두 같을 때만 비선호 스킬이 없는 결과를 앞에 둔다.
- 상위 `limit` 개만 힙(`topK.ts`)으로 유지해 `items` 로 반환하고, `total` 은 찾은 전체 개수.
- 상한: 리프 200만 회 또는 20초에 도달하면 중단하고 `truncated: true` (이때 total 은 최소 개수 → 화면에 'N건 이상').
- `onProgress` 는 약 100ms 마다 (최상위 분기 진행률, 찾은 수).

반환 직전 대표 조합을 `computeBuild` 로 다시 계산해 표시 값(스킬·남은 슬롯·방어력·비선호)을 채운다.

### 6.6 검증
테스트에서 모든 결과를 `resultToBuild` → `computeBuild` 로 다시 계산해
`missingRequirements` 가 비고, 슬롯이 전부 유효하고, `unwantedSkills/freeSlots/defense` 가 일치하는지 확인한다.
장식주 없이 찾기는 방어구만으로 조건을 채우는 실제 조합 수를 부위별 DP 로 따로 세어 결과 `variantCount` 합과 맞춰 본다.

## 7. 화면

공통: 한국어 UI, 데스크톱 2단 / 모바일 1단, 의미 기반 색상 토큰만 사용, 게임에서 추출한 아이콘·이미지·로고 사용 금지.

슬롯 표시(`SlotBadge`): 모양 = 종류(방어구 원, 무기 마름모), 색 = 레벨(`slot-1/2/3` 청록·보라·주황, 두 테마 모두
색각 이상 시뮬레이션에서 세 쌍이 다 구분되게 고름), 장식주가 들어 있으면 옅게 채운다.
남은 슬롯 요약(수동 세팅·검색 결과·내 세팅)은 무기 슬롯 먼저, 같은 종류면 레벨 높은 순 (`SlotList` 의 `sorted`).

모바일: 레이아웃은 화면 폭(`md`·`lg`)으로, 터치 크기·입력 방식은 포인터 종류(`pointer-coarse:`, `useCoarsePointer`)로 나눈다.
- 메뉴: `md` 미만에서는 제목 줄은 스크롤되어 사라지고, 폭을 똑같이 나눈 탭 메뉴만 화면 위에 붙는다.
  탭마다 스크롤 위치를 기억해 돌아가고, 지금 탭을 다시 누르면 맨 위로 올라간다 (`src/lib/scroll.ts`).
  탭 이름에는 선 아이콘(`TabIcon`)을 붙인다. 데스크톱 헤더는 이름 옆, 휴대폰은 이름 위 (옆에 두면 좁은 폭에서 '수동 세팅'이 넘친다).
  `md`~`lg` 헤더는 탭 5개 옆에 제목이 다 보이도록 아이콘을 뺀다.
- 수동 세팅·스킬 검색: `lg` 미만(1단)에서는 장비/결과, 조건/결과 중 하나만 보여 주고 화면 아래 조작 바(`MobileBar`)로 바꾼다.
  패널마다 스크롤 위치를 기억한다. 검색 버튼도 아래 바에 있고, 누르면 결과 패널로 넘어간다.
- 선택 상자(`Combobox`): 터치 기기에서는 입력 칸 아래로 펼친 목록이 키보드에 가리므로 검색 칸+목록 시트를 연다
  (휴대폰은 전체 화면, 태블릿은 위쪽 창). 탭 처리 중에 검색 칸에 포커스해야 iOS 가 키보드를 띄운다.
- 대화상자: 휴대폰에서는 화면 아래에 붙는 시트. 시트·대화상자는 키보드를 피하도록 보이는 영역(visual viewport)에
  맞춘다 (`src/lib/viewport.ts`). 열릴 때 포커스는 `data-autofocus` (터치 기기에서는 키보드가 가리지 않게 생략).
- 터치 기기에서 입력 요소는 16px (iOS 사파리 확대 방지, `index.css`), 버튼·선택 상자는 36~40px 로 커진다.
- `viewport-fit=cover`: 노치·홈 표시줄 영역은 `env(safe-area-inset-*)` 여백으로 피한다.

테마: 헤더에서 시스템 설정 따르기 / 라이트 / 다크를 고른다(localStorage `theme:v1`, 기본은 시스템 설정).
`<html data-theme="light|dark">` 에 따라 `index.css` 의 토큰 값이 바뀐다. 첫 화면 깜빡임을 막으려고
`index.html` 의 인라인 스크립트가 React 보다 먼저 같은 규칙으로 적용한다 (`src/lib/theme.ts` 와 함께 고친다).

### 7.1 수동 세팅 (`features/manual`)
- 장비 7칸(무기·머리·몸통·팔·허리·다리·호석) + 각 장비의 슬롯별 장식주 선택.
- 무기: 무기 종류 선택 → 무기 검색, 또는 '직접 입력'(슬롯·무기 스킬).
  거극 아티어 무기를 고르거나 '직접 입력'이면 붙은 시리즈·그룹 스킬을 하나씩 고르는 칸이 나온다 (`WeaponBonusSkills`,
  검색 조건과 공용, 칸 폭이 좁으면 한 줄에 하나씩). 거극 아티어 무기끼리 바꾸거나(격화 타입 등) 직접 입력으로 바꾸면 고른 스킬을
  그대로 둔다. 데이터 이름에 '거극 아티어'가 없어서 무기 목록에 붙여 보여 주고 그 말로도 찾게 한다 (`GOGMA_ARTIAN_NAMES`).
- 방어구: 부위별 검색(옵션에 레어도·슬롯·스킬 표시), 레어도 5~8이면 '초월' 체크.
- 호석: 내 호석 + 제작 호석 검색. 공유받은 세팅처럼 내 호석에 없는 호석은 '세팅 전용' 표시와 함께 이 세팅에 든 동안만
  목록 맨 위에 보이고(다른 호석으로 바꾸면 사라짐), '내 호석에 추가'로 내 호석에 넣으면 세팅이 그 호석을 가리킨다
  (내용이 같은 내 호석이 이미 있으면 그 호석으로 바꾼다).
- 장식주: 슬롯 종류·크기에 맞는 것만 표시. 장비를 바꾸면 그 장비의 장식주는 비운다.
- 최대까지 채우기: 장식주가 든 칸 옆 버튼. 그 장식주의 스킬(복합 장식주면 아직 최대가 아닌 첫 스킬)을 모든 장비의 빈 슬롯에
  그 스킬만 주는 장식주를 넣어 최대 레벨까지 올린다 (`decorationFill.ts`). 슬롯이 모자라도 버튼 문구는 같고 되는 데까지만 올린다.
  빈 슬롯마다 장식주 하나를 넣거나 비우는 0/1 배낭 DP 로, 가장 높이 올리는 배치 중 쓰는 슬롯의 Σ 레벨² 이 작은 것(큰 슬롯을 남김)
  → 장식주 수 → 장식주 크기 합 순으로 고른다. 무기 장식주는 Ⅰ·Ⅱ·Ⅲ 을 섞는다. 장식주가 든 슬롯은 건드리지 않는다.
  넣은 장식주와 결과 레벨을 알림으로 보여 주고, 알림의 '되돌리기'는 넣은 장식주가 그대로 있는 슬롯만 비운다.
- 요약: 발동 스킬(레벨/최대, 초과분, 출처), 시리즈/그룹 스킬(부위 수·단계·다음 단계, 거극 아티어 무기가 센 부위가 있으면
  '무기 포함'), 방어력, 내성, 남은 슬롯.
  발동 스킬을 누르면 스킬 설명·지금 레벨 효과·출처를 펼친다. '모든 레벨'은 Lv1~최대 효과를 모두 보여 주고 지금 레벨을 강조한다
  (1레벨 스킬은 버튼 없음).
- 게임 위에 띄우기: 다른 창 위에 늘 떠 있는 작은 창(Document Picture-in-Picture, PC 크롬·엣지 116+)에 부위별 장비·장식주(빈 슬롯 포함)와
  발동 스킬을 보여 준다(`GameOverlay`). 창에는 스타일·테마를 복사하고 내용은 포털로 그려 수정이 바로 반영된다(`src/lib/pip.ts`).
  게임이 전체 화면이면 위에 안 뜰 수 있어 처음 띄울 때 '테두리 없는 창' 안내를 보여 준다(`overlay-tip:v1`).
  미지원 브라우저는 크롬·엣지와 Steam 오버레이 핀을 안내하고, 터치 기기에서는 버튼을 숨긴다.

### 7.2 스킬 검색 (`features/search`)
- 조건: 원하는 스킬(+레벨), 비선호 스킬 + 모드(표시만 / 아예 제외), 무기, 호석(자동/내 호석만/고정/없음), 옵션(하위 랭크 포함, HR 100 장비 제외, 초월 적용, 장식주 없이 찾기).
- 거극 아티어 무기의 시리즈·그룹 스킬은 조건에 따로(`weaponSetSkillId`·`weaponGroupSkillId`) 두고, `buildRequest` 가
  거극 아티어 무기를 골랐거나 슬롯 직접 지정일 때만 요청 무기에 담는다 (다른 무기로 바꿨다 돌아와도 남아 있고,
  다른 무기의 요청 키는 그대로).
- HR 100 장비 제외: `buildRequest` 가 `hunterRank.ts` 목록의 방어구를 `excludedArmorIds` 로 넘기고(엔진은 그대로),
  자동 호석은 계열마다 HR 100 전에 만들 수 있는 가장 높은 등급을 쓴다.
- 원하는 스킬은 줄마다 체크로 켜고 끈다. 끈 스킬은 레벨과 함께 목록에 남고 `buildRequest` 에서만 빠진다
  (저장값 `required[i].off`, 없으면 켜짐). 요청에는 `off` 를 떼고 넣어 껐다 다시 켜면 이전 결과가 그대로 최신이다.
- 실행: `SearchClient` (취소 가능, 진행률 표시).
- 결과: 카드 목록. 부위별 대표 방어구 + 대체 후보 수(펼쳐서 선택), 장식주 요약, 스킬 칩(요구=초록, 시리즈·그룹=주황, 추가=회색, 비선호=빨강+금지 모양), 남는 슬롯, 방어력, '수동 세팅에서 열기'.
- 비선호 스킬이 든 결과도 같은 목록·같은 정렬에 섞는다 (예전처럼 맨 아래에 따로 모으면 남는 슬롯이 가장 많은 조합이 비선호
  스킬 하나 때문에 묻혔다). 카드 전체는 따로 표시하지 않고, 그 스킬 칩(빨강 + 금지 모양: 색각에 따라 초록과 헷갈리지 않게)과
  비선호 스킬이 붙은 부위·호석 옆의 그 스킬(예: `체술 2 · 앙심 1`), 비선호 스킬을 주는 장식주의 빨간 글씨로만 표시한다.
- 스킬 칩을 누르면 칩 목록 아래에 그 스킬의 효과가 열린다: 스킬 설명 + 지금 레벨 효과, 시리즈·그룹 스킬은 지금 단계 이름·부위 수·효과
  (마우스를 올려야 보이는 툴팁은 휴대폰에서 볼 수 없어서 누르는 방식으로 한다).
- 추가 스킬(회색) 칩의 효과 아래에는 비선호 스킬 넣기/빼기 줄이 붙는다. 결과를 만든 요청이 아니라 지금 조건을 고치고
  (`ExcludeControl`), 넣은 칩은 다시 검색할 때까지 빨강으로 둔다. 여러 개를 연달아 넣을 수 있게 바로 다시 검색하지는 않는다.
  원하는 스킬 목록(꺼 둔 것 포함)에 있는 스킬은 넣을 수 없다.
- 비교: 결과 카드의 '비교'로 최대 3개(`COMPARE_MAX`)를 골라 비교 창에서 나란히 본다. 칸 = 고른 결과, 행 = 요약(방어력·남는 슬롯) →
  부위별 장비(이름·레어도·슬롯·장비 자체 스킬) → 장식주 개수 → 스킬(원하는·비선호·시리즈/그룹·추가) → 내성.
  비교 창은 내 세팅과 함께 쓴다(`features/compare`: 창 `CompareDialog`, 행 계산 `compareRows.ts`, 아래 비교 바 `CompareTray`).
  모든 칸이 같은 행은 흐리게 두고 '다른 점만 보기'면 숨긴다. 방어력은 가장 높은 칸을 초록, 나머지는 차이(−6)를 붙인다.
  장비 행은 장비만 비교한다(장식주를 어느 슬롯에 넣었는지는 장식주·남는 슬롯 행에서 본다). 거극 아티어 무기는 붙은 시리즈·그룹
  스킬도 보여 주고, 같은 무기라도 스킬이 다르면 다른 장비로 본다. 방어구는 초월 여부 대신 초월을
  반영한 슬롯으로 비교한다(`equipmentKey`): 레어도 7·8 은 초월해도 칸이 똑같아서 같은 장비로 보고(늘어난 방어력은 방어력 행),
  초월하면 슬롯이 느는 레어도 5·6 은 다른 장비로 남긴다.
  휴대폰은 행 이름을 값 위 한 줄에 따로 두고 값만 칸으로 나눈다 (360px 폭에 3칸).
- 검색 결과 비교 목록(`search/compareList.ts`)은 세팅 단위다(`buildKey`: 무기·방어구·초월·호석·장식주 배치).
  카드에서 대체 방어구를 고르면 다른 세팅이라 '비교'가 꺼진 것으로 보이고, 따로 넣어 대체 방어구끼리도 비교할 수 있다('대체 장비').
  목록은 검색 화면 state 라 다시 검색해도 남고(브라우저에 저장하지 않음), 새 결과에 같은 세팅이 있으면 그 번호·요청으로
  옮기고(`relinkEntries`: 정렬을 바꿔도 #N 이 맞는다) 없으면 '이전 검색'으로 둔다. 데스크톱은 결과 열 끝의 sticky 비교 바,
  휴대폰·태블릿은 아래 조작 바의 '비교 N' 버튼으로 연다. 비교 창 안에서 저장하면 알림이 모달에 가려지므로 버튼 글자('✓ 저장함')로 알린다.

### 7.3 내 호석 (`features/talismans`)
- 감정 호석 등록/수정/삭제: 이름, 레어도(선택), 스킬 최대 3개(+레벨), 슬롯 최대 3개(종류+레벨). localStorage 저장.
- 내 호석에는 실제로 가진 호석만 둔다. 스킬 검색의 '자동'·'내 호석만'이 이 목록을 쓰므로, 공유받은 세팅의 호석은
  넣지 않고 그 세팅에만 담는다 (세팅 전용 호석, §8.2).
- 삭제: 그 호석을 쓰던 내 세팅·수동 세팅은 같은 내용의 세팅 전용 호석으로 바꿔 그대로 둔다 (`detachTalisman`,
  확인 창에 쓰는 곳을 적는다). 예전에는 '삭제됨'으로 깨져서, 공유받으며 쌓인 호석을 지우면 저장한 세팅이 망가졌다.

## 8. 저장·공유 (`src/core/share`, `src/core/savedBuilds.ts`, `features/saved`)

로그인 없이 동작한다. 서버가 필요해지면 같은 형식을 그대로 클라우드에 올리면 된다.

- **내 세팅**: `SavedBuild[]` 를 localStorage(`saved-builds:v1`)에 저장. 첫 저장 때 `navigator.storage.persist()` 요청
  (사파리는 7일 넘게 방문하지 않으면 저장소를 지울 수 있어 백업 내보내기를 함께 안내한다).
- **세팅 비교**: 내 세팅 카드의 '비교'로 최대 3개를 골라 스킬 검색과 같은 비교 창(§7.2, `features/compare`)에서 본다.
  원하는 스킬이 없으니 스킬은 시리즈·그룹 / 발동 스킬로만 나누고, 칸 버튼은 '불러오기'(수동 세팅을 바꿀지 확인).
  비교 목록은 화면 state(id, 넣은 순서)라 지운 세팅은 빠지고 이름·내용을 고치면 바로 반영된다. 이 화면은 아래 조작 바가 없어
  비교 바를 모든 폭에서 쓴다 (휴대폰 폭은 이름 칩 대신 개수만).
- **공유 코드 / 링크**: 세팅 1개를 짧은 문자열로. 링크는 `<사이트>#b=<코드>` — 열면 불러올지 묻는다.
- **백업**: 내 세팅 전체 + 내 호석을 백업 코드(복사·붙여넣기용 글)나 JSON 파일로 내보내기/가져오기(병합).
  두 탭의 데이터를 함께 담으므로 어느 한쪽이 아닌 따로 된 '백업' 탭(`BackupPage`)에 두고, 내 세팅·내 호석 설명에서 이 탭으로 잇는다.
  내보내기·가져오기는 대화상자 없이 탭에 바로 보인다. 모든 탭이 마운트돼 있으므로 백업 코드는 이 탭을 볼 때만 만든다.

### 8.1 안정적인 식별자
MHDB 의 `id` 는 DB 번호라 데이터를 다시 만들면 바뀔 수 있으므로 공유 코드에는 **게임 내부 id(gameId)** 를 쓴다
(모두 int32, 아래 키로 유일함을 데이터 생성 시 검증).

| 대상 | 키 |
|---|---|
| 스킬 | `skill.gameId` |
| 방어구 | (`armorSet.gameId`, 부위) |
| 무기 | (무기 종류, `weapon.gameId`) |
| 장식주 | `decoration.gameId` |
| 제작 호석 | (`charm.gameId`, 등급 `level`) |

### 8.2 공유 코드 형식 v1·v2
바이트열을 base64url(패딩 없음)로 쓴다. `varint` = LEB128 부호 없는 정수, `zz(n)` = zigzag 인코딩(int32), `str` = u8 바이트 길이 + UTF-8 (최대 60바이트, 글자 경계에서 자름).

```
u8   version = 1 | 2 (2 = 무기 tag 3·4 가 든 코드)
무기  u8 tag: 0 없음 | 1 DB | 2 직접 입력 | 3 DB + 거극 아티어 스킬 | 4 직접 입력 + 거극 아티어 스킬
      1 → u8 무기 종류 인덱스(WEAPON_KINDS), varint zz(gameId)
      2 → u8 슬롯 수, u8 레벨…, u8 스킬 수, (varint zz(스킬 gameId), u8 레벨)…
      3·4 → 1·2 와 같고 이어서 u8 스킬 수(1~2), varint zz(스킬 gameId)… (시리즈/그룹은 스킬 종류로 가린다)
방어구 ARMOR_KINDS 순서로 5번: u8 tag: 0 없음 | 1 장착 | 2 장착+초월, 이어서 (1·2) varint zz(세트 gameId)
호석  u8 tag: 0 없음 | 1 제작 | 2 직접 입력
      1 → varint zz(charm gameId), u8 등급
      2 → str 이름, u8 레어도(0 = 없음), u8 스킬 수, (varint zz(스킬 gameId), u8 레벨)…, u8 슬롯 수, u8 (종류<<2 | 레벨)… (종류 0 방어구, 1 무기)
장식주 EQUIP_KEYS 순서로 7번: u8 칸 수 n(≤8), u8 비트마스크(i번 칸 채움), 채워진 칸마다 varint zz(장식주 gameId)
이름  str (0 = 없음)
```

- 디코딩 시 버전이 다르거나 바이트가 모자라면 `ShareCodeError`.
- 버전은 읽을 수 있는 가장 새 것(`FORMAT_VERSION` = 2)까지 받고, 쓸 때는 필요한 가장 낮은 버전을 적는다: 거극 아티어 스킬이 없는
  세팅의 코드는 예전과 똑같고(백업 병합의 '코드가 같으면 건너뛰기'도 그대로), 갱신 전 페이지는 v2 코드를 '새로운 형식'으로 안내한다.
  `WeaponChoice` 의 거극 스킬·검색 조건의 `weaponSetSkillId` 등은 예전 저장값을 그대로 읽는 추가라 저장 키 버전을 올리지 않았다.
- 현재 데이터에 없는 항목은 비우고 `missing` 에 한국어로 적는다 (예: '머리 방어구', '장식주 2개', '무기 스킬 1개').
- 직접 입력 호석은 세팅 전용 호석(`TalismanChoice` 의 `{ type: 'inline', talisman }`: 내용을 세팅에 그대로 담음)으로 꺼낸다.
  열거나 저장할 때 `linkTalisman` 이 내용이 같은 내 호석(`sameTalisman`, 이름 무시)이 있으면 그 호석을 가리키게 바꾸고(슬롯 순서가
  다르면 장식주 위치를 맞춤), 없으면 세팅 전용 그대로 둔다. 내 호석에 새로 넣지는 않는다 — 예전에는 새로 넣어서 공유받은 세팅을
  열어 보기만 해도 내 호석이 늘었다. 세팅 전용 호석도 내 호석과 똑같이 내용으로 인코딩하므로 코드 형식은 그대로다.
  저장값(`manual-build:v1`·`saved-builds:v1`)도 예전 값을 그대로 읽는 추가라 키 버전을 올리지 않았다.

### 8.3 백업 (파일 / 백업 코드)
`BackupFile` (`app: 'mhwilds-sim'`, `kind: 'backup'`, `version: 1`). 세팅은 공유 코드(이름은 빼고 `name` 에 따로)로,
내 호석은 id 를 뺀 내용 + 스킬 gameId(`skillGameIds`)로 담는다. 가져올 때 쓰지 않는 값(호석 id, 코드 속 이름)을 빼서
백업 코드를 짧게 한다. 예전 파일처럼 들어 있어도 무시할 뿐 똑같이 가져온다.
가져오기는 병합: 호석은 내용이 같으면 재사용, 세팅은 이름과 코드가 모두 같으면 건너뛴다. 새 항목은 새 id 를 받는다.
세팅에 든 세팅 전용 호석은 내 호석에 넣지 않는다 (백업의 `talismans` 는 내 호석만, 세팅은 `linkTalisman` 으로 연결).
`importBackup` 은 순수 함수라 화면은 결과(추가될 수)를 먼저 보여 주고, 확인하면 그 결과를 그대로 반영한다.

- **파일**: `BackupFile` JSON (`mhwilds-sim-backup-<날짜>-<시각>.json`).
- **백업 코드**: `mhwilds-backup-1.` + base64url(deflate-raw(UTF-8 JSON)). 파일을 다루기 불편한 휴대폰에서 메신저·메모 앱으로
  옮기는 용도. 압축은 `CompressionStream`(사파리 16.4+). 앞머리의 숫자는 코드 형식(압축 방식) 버전이라 바뀌면 올리고,
  더 큰 숫자는 '새로운 형식'으로 안내한다. 붙여 넣은 글에서 앞머리를 찾고 그 뒤의 공백·줄바꿈은 무시한다.
  풀었을 때 8MB 를 넘으면 거절한다(압축 폭탄 방지). '.' 이 있어 공유 코드(base64url 만)와 섞이지 않으므로
  내 세팅의 '코드로 가져오기'와 백업 탭의 '가져오기' 어느 쪽에 붙여 넣어도 알아서 처리한다.
  길이는 대략 기본 600~1,000자 + 세팅 하나에 100~130자 (세팅 10개 ≈ 2,300~2,500자, 20개 ≈ 3,400~4,100자).
